# 财务管理 APP v0.5.0 版本记录

> 日期：2026-10-19
>
> 状态：已完成代码改动，待构建 APK 并真机验证
>
> 版本目标：自动记账从"回 APP 才能看到弹窗、只能取消"升级为"在微信/支付宝支付页直接弹出当场记账卡片"

## 1. 新增：原生悬浮窗当场记账

- 新增 `OverlayEntryManager`（`app/src/main/java/app/financemanager/capture/overlay/`）：
  - 通过 `SYSTEM_ALERT_WINDOW` + `WindowManager.addView` 在微信/支付宝等支付 APP 上层直接弹出底部卡片。
  - 纯原生 View，不加载 WebView，毫秒级显示，不打断当前 APP。
  - 卡片内容：金额、商户名、来源标签，三个按钮「忽略」「改分类」「✓ 记一笔」。
  - 点「记一笔」：通过 Capacitor 事件 `overlayCommitRequest` 抛给前端，前端用规则推荐的账户和分类直接入账，成功后原生 Toast 提示。
  - 点「改分类」：收起悬浮窗，把 MainActivity 拉到前台，弹完整 WebView 记账卡片（分类/账户可选）。
  - 点「忽略」：从 Room 捕获队列删除该记录。
- `AndroidManifest.xml` 新增 `SYSTEM_ALERT_WINDOW` 权限声明。
- `PaymentCapturePlugin` 新增三个桥接方法：
  - `canDrawOverlay()` / `openOverlaySettings()`：检查与跳转悬浮窗权限。
  - `onOverlayCommitDone({success, message})`：前端入账完成后回调，原生关悬浮窗并 Toast。
- 触发点接入：
  - `PaymentAccessibilityService.writeToQueue` 在写库后调 `OverlayEntryManager.maybeShowOverlay`。
  - `PaymentNotificationListenerService` 同样接入。
  - 任意线程可调用，内部 post 到主线程；已有悬浮窗在显示时不重复弹。

## 2. 修复：回 APP 后弹窗只有金额、只能取消

- `stores/capture-entry.ts` 的 `loadOptions()`：
  - 原来 `ledgerId` 未就绪时直接 return，导致账户/分类列表为空、确认按钮永远 disabled。
  - 改为指数退避重试 4 次（0/150/400/900ms），等账本就绪后自动加载。
  - 加载失败时显示"点此重试"。
- `components/CaptureQuickEntrySheet.vue`：
  - 加载中显示"正在加载账户与分类…"提示。
  - 加载失败显示可点击的重试行，不再静默空白。

## 3. 设置页：悬浮窗权限引导

- `views/CaptureSettingsView.vue` 新增"当场弹窗（悬浮窗）"卡片：
  - 显示当前权限状态（已开启/未开启）。
  - 按钮跳转系统"显示在其他应用上层"设置页。
  - 进入页面和从系统设置返回时自动刷新权限状态。

## 4. 已知限制（一期 MVP）

- 悬浮窗内不展示分类/账户横排，「记一笔」按钮直接用规则推荐的账户和分类；想改分类点「改分类」进入完整卡片。
- 微信/支付宝之外的来源（淘宝、美团等）一期不弹悬浮窗，继续走原 WebView 路径或截图→豆包 JSON→剪贴板流程。
- 小米 HyperOS 上需手动在系统设置里打开"显示在其他应用上层"（无障碍设置页有入口）。
