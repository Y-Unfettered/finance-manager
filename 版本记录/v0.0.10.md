# 财务经理 APP v0.0.10 版本记录

> 日期：2026-08-03
>
> 状态：开发完成，待最终发布核验
>
> 对应里程碑：Sprint 3+4 合并，数据导入、备份恢复与导出闭环

## 1. 本版本目标

合并 Sprint 3 与 Sprint 4，把"旧账能够进来"和"数据不会丢"两件事一次性打通，使应用具备 MVP 候选版的数据主权能力：用户可以把已有 CSV 账单批量导入、整批撤销，随时生成完整备份包并在空库恢复，也能将交易导出为 CSV 或 JSON。

## 2. 新增内容

### 通用 CSV 导入（Sprint 3）

- 新增 `ImportView` 四步向导：选择文件 → 字段映射 → 预览 → 完成，顶部带步骤指示器。
- 选择 CSV 文件后自动识别表头并按关键字（日期/金额/类型/商户等）模糊匹配生成默认字段映射。
- 字段映射支持为每个系统字段（日期、金额、类型、时间、商户、备注、转出/转入账户、分类、来源交易号）选择对应 CSV 列或"不导入"；日期与金额为必填项。
- 账户映射与分类映射采用手动添加映射对方式，分类按支出/收入分组。
- 预览阶段调用 `ImportService.previewCsv`，展示总行数、有效行数、错误数与重复数；错误列表最多显示 20 条，有效行预览前 5 行。
- 当类型列缺失时，根据分类性质或金额正负自动推断支出/收入。
- 确认导入后调用 `ImportService.executeImport`，生成导入批次并写入交易；完成后展示成功/失败数与批次 ID。

### 导入批次撤销（Sprint 3）

- 新增 `ImportBatchesView`，按时间倒序列出所有导入批次，显示文件名、来源、状态徽章、成功/失败/重复统计与创建时间。
- 有效批次支持撤销：确认弹窗 → 调用 `ImportService.voidBatch`，将批次内交易状态置为 `void` 并标记批次为已撤销。
- 撤销不影响其他批次的数据；同一文件重复导入会因来源指纹命中而跳过写入。

### 完整本地备份与恢复（Sprint 4）

- 新增 `BackupView`，分为"创建完整备份"与"从备份恢复"两个区块。
- 备份包为 JSON 格式，包含格式标识、版本、schema 版本、应用版本、创建时间、各表记录数、完整数据与 SHA-256 校验值。
- 创建备份调用 `BackupService.createBackupJson` 并通过 `saveTextFile` 写入 Documents 目录（原生）或触发浏览器下载（Web）。
- 恢复前先调用 `BackupService.verifyBackupJson` 校验格式与校验值，展示备份创建时间、记录总数与 schema 版本，需用户二次确认。
- 确认后调用 `RestoreService.restoreFromJson`，恢复前自动生成当前库的备份（`preRestoreBackup`），便于回滚。
- 页面底部展示当前数据库各表记录数概览。

### CSV / JSON 导出（Sprint 4）

- 新增 `ExportView`，支持 CSV 与 JSON 两种格式，可选"包含已撤销交易"。
- 调用 `ExportService.exportTransactionsCsv / exportTransactionsJson`，导出按时间倒序的全部交易，金额、日期、类型标签、账户、分类、商户、备注均格式化。
- 导出文件通过 `saveTextFile` 写入 Documents 目录或浏览器下载。

### 数据管理入口

- 新增 `ProfileView`（"我的"页）替代原占位页，集中放置导入账单、导入批次管理、备份与恢复、导出账单四个入口，并展示应用名称、版本、账本与数据库版本。
- 底部导航"我的"指向新页面。

### 服务依赖注入

- `ImportService`、`BackupService`、`RestoreService`、`ExportService` 各自暴露 `InjectionKey` 与 `useXxxService` 组合式函数。
- `main.ts` 在数据库就绪后统一提供四个服务，页面通过 `inject` 获取，与 `FinanceService` 注入模式一致。

### 跨平台文件 I/O

- 新增 `utils/file-io.ts`：`readFileAsText` 通过 `input[type=file]` 读取文件；`saveTextFile` 在原生平台写入 Capacitor `Directory.Documents`，在 Web 平台触发浏览器下载。

## 3. 财务口径

- 导入产生的交易与手工记账完全等价，复用同一套复式分录规则；支出/收入/转账三类交易的账户与分类影响与手工录入一致。
- 导入批次撤销只把对应交易状态置为 `void`，不物理删除，账户余额会回退到撤销前状态。
- 备份与恢复覆盖全部 9 张数据表（schema_migrations、ledgers、accounts、categories、import_batches、transactions、entries、receivables、payables），恢复后账户余额、资产负债与交易数量保持一致。
- 备份校验值不匹配或 schema 版本高于当前应用时拒绝恢复。
- 导出的金额按交易类型标注正负：支出、信用消费、还款为负数。

## 5. 已知限制

- CSV 导入暂只支持支出、收入、转账三类；信用消费、还款、退款、借出/借入需后续补齐导入分支。
- 钱迹专用适配器尚未实现，待用户提供脱敏真实导出文件后开发。
- 应用锁（PIN）与最近任务隐私处理未在本版本完成，推迟到 0.1.0。
- migration 前自动备份与失败回滚为服务层逻辑，尚未在 `bootstrap` 中接入自动触发。
- 备份文件目前写入应用 Documents 目录，自动备份到用户选择位置的能力在 1.0 版本提供。
