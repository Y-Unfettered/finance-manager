> 日期：2026-08-03
>

## 1. 本版本目标

建立能够长期演进的本地账务数据地基，并用自动化测试证明首批业务交易能够生成正确、平衡的复式分录。

本版本仍不是可日常使用的业务 MVP，不写入用户真实财务数据。

## 2. 新增内容

### SQLite 与 Android

- 接入与 Capacitor 8 兼容的 `@capacitor-community/sqlite` 8.1.0。
- SQLite 插件已同步到 Android Gradle 工程。
- Android 原生启动时自动建立 `finance_manager` 数据库并执行待处理 migration。
- Pinia 增加数据库初始化状态、schema 版本和错误信息。
- 组件基线页增加 SQLite 状态文字，方便后续真机诊断。

### Schema v1

- `schema_migrations`：记录已执行的数据库版本。
- `ledgers`：本地账本与本位币。
- `accounts`：现金、银行、平台、受限资产、预付、投资、应收和负债账户。
- `categories`：收入/支出分类及父子层级。
- `transactions`：业务交易、状态、金额、时间、对方与自动捕获元数据。
- `entries`：借方/贷方分录，且每条分录只能指向账户或分类之一。
- `account_balances`：根据已入账分录实时计算资产和负债余额。
- `transaction_balances`：暴露每笔交易的借贷合计，供一致性检查。
- 增加常用查询索引和跨账本分录阻断触发器。
- 金额统一为正整数分；货币在首发阶段只允许 `CNY`。
- 账户类型与正常余额方向在数据库层保持一致：资产/应收为借方余额，负债为贷方余额。

### Migration runner

- migration 版本必须为严格递增的正整数。
- 空库自动创建 schema v1。
- 重复启动不会重复执行已应用 migration。
- 每个 migration 与其版本记录在同一个 SQLite 事务内执行。
- migration 失败时完整回滚，不留下半张表或虚假版本记录。
- 数据库版本高于当前 APP 能力时拒绝启动迁移，避免静默降级破坏数据。

### 账务领域规则

- 建立账户类型、正常余额、分类方向、分录方向和交易草稿类型。
- 支出：借记支出分类，贷记付款资产账户。
- 收入：借记收款资产账户，贷记收入分类。
- 账户转账：借记转入资产账户，贷记转出资产账户，不产生收入或支出。
- 信用消费：借记支出分类，贷记信用负债，同时增加支出与负债。
- 拒绝零金额、负数、浮点分、超过安全整数范围的金额。
- 拒绝同账户转账、分类方向错误和资产/负债账户角色错误。

### 工程路径

- 将本地工程工作路径从中文目录迁移为 `D:\finance-manager`。
- 在英文路径使用正常 Gradle 工作线程完成构建，中文路径下出现的资源合并临时目录异常未再发生。

## 3. 修改与调整

- 前端版本由 `0.0.1` 更新为 `0.0.2`。
- Android `versionCode` 由 `1` 更新为 `2`。
- Android `versionName` 由 `0.0.1` 更新为 `0.0.2`。
- 应用启动流程改为先初始化原生 SQLite，再挂载 Vue 页面；Web 开发环境明确跳过原生数据库。
- SQLite 连接版本读取统一使用当前最新 schema 版本，避免后续 migration 增加时遗漏更新。

## 4. 修复内容

- 通过迁移英文目录规避 Windows 中文路径下 Gradle `mergeDebugResources` 偶发找不到临时 XML 文件的问题。
- schema 约束阻止信用卡被错误设置为借方余额账户。
- migration runner 阻止不连续或未知数据库版本继续运行。

## 5. 数据库与兼容性

- 新增 migration：`001_initial_finance_schema`。
- `v0.0.1` 尚未创建业务数据库，因此升级到本版会直接创建空的 schema v1，不涉及用户数据迁移。
- migration 可重复执行，数据库重复打开不会重复建表。
- 本版数据库连接尚未启用加密；正式写入个人数据前将接入密钥管理与 SQLCipher 配置。
- 不需要用户手工操作。

## 7. 已知问题与限制

- 尚无 Repository 负责原子写入交易与分录；本版先完成 schema、迁移和纯领域规则。
- 尚无创建账本、账户和分类的业务界面。
- 数据库尚未启用加密和 Android Keystore 密钥管理，不能开始录入真实敏感数据。
- Android 启动数据库初始化已接入，但尚未在小米 17 Pro Max 真机验证首次创建与重启持久化。
- 完整开发依赖审计有 3 个中等级告警，链路为开发期 `@capacitor/cli → xcode → uuid`；它仅用于 iOS 工具链，不进入 Android 生产依赖，当前生产审计为 0。后续随 Capacitor 官方修复升级。
- 标准 Gradle Wrapper 8.14.3 仍未缓存；当前使用与 Android Gradle Plugin 兼容的本机 Gradle 8.13 成功构建。

## 8. 下一版本计划

### 版本号

`v0.0.3`

### 核心目标

让账本、账户、分类和第一笔交易能够通过 Repository 安全写入 SQLite，并能重新读取和核对账户余额。

### 计划内容

- 建立统一 ID、UTC 时间和事务执行规范。
- 实现 `LedgerRepository`、`AccountRepository`、`CategoryRepository` 和 `TransactionRepository`。
- 实现账本初始化服务：创建单账本、基础分类和常用账户。
- 将交易草稿与分录在同一个 SQLite 事务内写入。
- 实现账户余额与按时间读取流水的查询接口。
- 建立固定测试账套，验证关闭并重开数据库后数据仍然正确。

### 明确不做

- 不制作正式首页。
- 不实现钱迹/CSV 导入。
- 不实现自动记账。
- 不实现预算、报表、还款、退款和应收款业务。
