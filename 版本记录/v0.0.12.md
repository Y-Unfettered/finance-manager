# 财务经理 APP v0.0.12 版本记录

> 日期：2026-08-03
> 状态：已完成
> 对应里程碑：v0.1.0 前的迭代版本

## 1. 本版本目标

修复导入 Excel/JSON 文件时触发的数据库 CHECK 约束错误，以及字段映射列表中"日期"和"时间"字段同时显示的 UI 问题。

## 2. 新增内容

- 新增数据库 migration v5（[005_import_batches_source_v5.ts](file:///d:/finance-manager/app/src/db/migrations/005_import_batches_source_v5.ts)），重建 `import_batches` 表，将 `source` 字段的 CHECK 约束从 `('csv', 'qianji', 'other')` 扩展为 `('csv', 'xlsx', 'json', 'qianji', 'other')`，支持导入 Excel 和 JSON 文件。
- migration v5 采用"备份临时表 → DROP 旧表 → 创建新表 → 恢复数据 → 删除备份"五步流程，避免 RENAME TABLE 时 SQLite 自动更新 transactions 表外键引用的问题。

## 3. 修改与调整

- `ImportView.vue` 中 `FIELD_OPTIONS` 从静态常量改为动态 `computed`：只有当表头中同时存在独立的"日期"列和"时间"列时才显示"时间"字段。
- 前端版本更新为 `0.0.12`，Android 更新为 `versionCode 12 / versionName 0.0.12`。

## 4. 修复内容

- 修复导入 Excel（.xlsx/.xls）或 JSON 文件时报 `CHECK constraint failed: source IN ('csv', 'qianji', 'other')` 错误的问题。原 v4 migration 的 CHECK 约束未覆盖 `xlsx` 和 `json` 两种来源类型。
- 修复字段映射列表中"日期"和"时间"两个字段同时显示的问题。单列含完整日期时间（如钱迹"时间"列）应映射到 date，不再显示多余的 time 字段。

## 5. 数据库与兼容性

- 是否新增 migration：是（v5：`import_batches_source_v5`）
- 是否兼容旧备份：是
- 是否需要用户操作：重新安装 APK 即可，应用启动时会自动从 v4 升级到 v5（旧 import_batches 数据会保留并迁移到新表）

## 7. 已知问题与限制

- migration v5 重建表时需要短暂关闭外键检查（`PRAGMA foreign_keys = OFF`），迁移完成后重新开启。在迁移过程中如果发生意外崩溃，需要从备份恢复。
- migration v5 不保留 `import_batches_old` 表（与 RENAME 方案不同），因此迁移后无法回滚到 v4。建议在迁移前手动备份（v0.1.0 将实现 migration 前自动备份）。
