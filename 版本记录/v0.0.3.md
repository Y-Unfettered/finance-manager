# 财务经理 APP v0.0.3 版本记录

> 日期：2026-08-03
>
> 状态：已完成
>
> 对应里程碑：Sprint 0 完成

## 1. 本版本目标

让账本、账户、分类和交易能够通过 Repository 安全写入 SQLite，并证明交易关闭重开后仍可读取、账户余额保持正确。

本版本完成 Sprint 0 数据地基；尚未提供正式的用户记账页面。

## 2. 新增内容

### SQLite 执行能力

- `SqliteExecutor` 增加带参数的 `executeSet` 批处理接口。
- Capacitor Android 与 Node.js 测试适配器使用一致的参数化 SQL 契约。
- 批量语句可选择在同一个事务内执行；任意一条失败时完整回滚。
- 测试适配器支持真实 SQLite 文件关闭和重新打开。

### 领域基础设施

- 新增 `LedgerRecord`、`AccountRecord`、`CategoryRecord`、`StoredTransaction` 和 `StoredEntry`。
- 新增带实体前缀的随机 ID，避免依赖数据库自增主键。
- 新增统一 `Clock` 接口，持久化创建时间使用 UTC ISO 8601。
- 用户输入的带时区交易时间在写库前统一转成 UTC。

### Repository

- `LedgerRepository`：读取第一个账本、创建账本、原子创建账本及默认数据。
- `AccountRepository`：创建账户、读取记账账户引用、账户列表与实时余额。
- `CategoryRepository`：创建分类、读取记账分类引用和分类列表。
- `TransactionRepository`：交易与分录原子写入、交易详情、账本流水和数量查询。
- Repository 将 SQLite `NULL` 显式转换为 TypeScript 可选字段。
- 账户写入前校验类型和正常余额方向一致。

### 默认账本初始化

- APP 首次启动时自动创建“日常账本”。
- 自动创建“现金”资产账户。
- 自动创建 8 个支出分类：餐饮、交通、购物、居住、医疗、娱乐、人情往来、其他支出。
- 自动创建 5 个收入分类：工资、奖金、红包、投资收益、其他收入。
- 重复启动读取已有账本，不重复创建默认数据。
- 账本、现金账户和全部分类在一个事务中创建。

### 查询与持久化验证

- 账户余额直接读取 schema v1 的 `account_balances` 视图。
- 流水按交易发生时间倒序读取。
- 交易详情返回交易头和全部分录。
- 固定测试账套覆盖工资收入、银行卡支出、转入微信和信用卡消费。
- 测试账套期望余额：银行卡 `976,845` 分、微信 `20,000` 分、信用卡负债 `16,652` 分。
- 新增真实 SQLite 文件关闭并重新打开后的账本、交易和余额断言。

## 3. 修改与调整

- 前端版本由 `0.0.2` 更新为 `0.0.3`。
- Android `versionCode` 由 `2` 更新为 `3`。
- Android `versionName` 由 `0.0.2` 更新为 `0.0.3`。
- Android 数据库启动完成后将当前账本 ID 写入 Pinia 运行时状态。
- 组件基线页显示“SQLite 已就绪 · Schema v1 · 账本已初始化”。
- `validation/` 用于保存本地真机验证产物，默认不提交 Git。
- 补充更新 `v0.0.2` 真机安装验证结果，不移动原版本标签。

## 4. 修复内容

- 修复业务层只能生成分录但无法写入数据库的断层。
- 修复多条 INSERT 分开执行可能留下“有交易、无完整分录”的风险。
- 修复交易时间可能以不同本地时区格式直接保存的问题。
- 修复 SQLite `NULL` 与 TypeScript 可选字段类型不一致的问题。

## 5. 数据库与兼容性

- 本版本不新增 migration，继续使用 schema v1。
- 从 `v0.0.2` 覆盖安装后，已有空数据库直接复用并初始化默认账本。
- 已有账本时不重复初始化；升级不需要用户操作。
- 交易和分录写入使用单个 SQLite 事务，外键失败时交易头同步回滚。
- 数据库仍未启用加密，不应录入真实敏感财务数据。

## 7. 已知问题与限制

- 当前只有 Repository 和测试能够创建账户、分类和交易，尚无正式业务表单。
- 组件基线页仍然显示演示金额，不读取真实账本余额。
- 数据库尚未加密，Android Keystore 密钥管理未实现。
- 当前只有支出、收入、资产账户转账和信用消费，尚未实现还款、退款、余额调整和应收款。
- 完整开发依赖审计仍有 3 个中等级告警，来源为不进入 Android 生产包的 iOS 开发工具链。
- 标准 Gradle Wrapper 8.14.3 尚未缓存，当前使用本机 Gradle 8.13。
