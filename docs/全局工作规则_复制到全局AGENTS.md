# 全局工作规则（所有项目通用）

> 本文件是跨项目通用的协作流程。任何开发类改动都必须遵守。
> 项目相关的细节（打包命令、目录约定等）写在各项目根目录的 `AGENTS.md`。

## 核心原则

**没有任何改动可以在没有经过用户确认的情况下进行。** 哪怕是我认为的"小地方""顺手修一下"，
也必须先提出、得到确认后再改。用户不知道的改动等于制造"不明状态"。

## 固定流程（六步，不可跳步）

### 第 1 步：沟通想法
- 用户提出需求。
- 我回复：对需求的理解、现在的情况、建议怎么做、方案取舍、风险点。
- 用户确认或调整，直到方案敲定。

### 第 2 步：编写任务文档
- 方案确认后，**开工前**在项目 `docs/` 下建 `当前任务.md`（复制 `docs/当前任务模板.md`）。
- 必须写清：目标、范围（做什么/明确不做什么）、验收标准、涉及文件、风险点、进度勾选表。
- 文档写完**先发给用户过目**，用户说 OK 才开工。

### 第 3 步：开发
- 严格按文档执行。每完成一项回填进度勾选表。
- 执行中发现文档没覆盖的情况，**停下来先和用户确认**，不要自行决定。

### 第 4 步：打包与测试
- 开发完成后打包（命令见项目 `AGENTS.md`）。
- 打包后告诉用户：APK/产物位置、文档位置、以及**本次要重点测试哪几处**（测试清单）。

### 第 5 步：用户反馈
- 用户测试后反馈问题。有问题：回到第 1 步沟通确认 → 再写文档 → 再开发，往复直到完善。

### 第 6 步：收尾归档
- 完成后把 `docs/当前任务.md` 改名归档到 `docs/归档/`，下一个任务新建。

## 断点保护（重要）

上下文会压缩、会丢失。**不要指望一个对话记住所有历史**——要让任何新对话都能从项目文件里
"重新读档"恢复现场：
- 状态一律写进 `docs/当前任务.md`，不要只留在对话里。
- 每次对话开始先读项目根 `AGENTS.md` 和 `docs/当前任务.md`，再动手。
- 中途被中断（额度用完/上下文超限）时，**必须先更新 `docs/当前任务.md`**，写清做到哪、卡在哪、下一步做什么。

## 沟通语言
用中文。
