## 1. 逐项变更说明（改了什么 / 为什么）

### 1.1 确认入账主链路（`9e1e4ca`）——本次最重要的一笔

**背景**：审查发现自动记账的"确认入账"三条路径（待确认列表、当场弹窗、悬浮窗提交）在运行时**必然失败**：`capture-inbox-service.ts` 的 `confirmEvent()` 在异步上下文调用 `useFinanceService()`，而它内部是 Vue 的 `inject()`——异步栈里恒返回 `undefined`，永远抛"账务服务不可用"。

**改法**：
- `confirmEvent()` 改用 main.ts 启动时挂在 `window.__financeService` / `appStore.financeService` 的全局实例。
- **方向分派**：原来硬编码 `createExpense`，收红包（income）确认后被记成支出。现在按 `event.direction` 分派：`income → createIncome`；`expense/refund → createExpense`；`transfer → 显式抛错`（转账需要选转入账户，一键确认没有这个 UI）。
- **CaptureInboxView 确认弹窗**：收入捕获自动切换收入分类池；转账事件显示"去记账"按钮，跳 `/transactions/new?mode=transfer&direction=transfer&captureId=...` 完整记账页（事件保持 pending，由用户处理或 7 天后自动清理）。
- **P0-3 防重复入账**：`createExpense` 成功后的 `acknowledgeEvents()` 原来没有 try-catch——它一失败 UI 会把"已入账"当"入账失败"展示，用户再点一次就重复入账。现在捕获异常只记日志，绝不上抛。
- 顺带补传 `fingerprint`（原来 inbox 路径确认不写指纹，与 RecordSheet 路径防重能力不一致）。

**⚠️ 接手注意**：`confirmEvent` 依赖 `window.__financeService` 这个**约定**——main.ts 数据库就绪后写入。如果有新代码要在非 setup 上下文调账务服务，照这个模式走，**不要用 inject()**（stores/capture-entry.ts 里原有注释也踩过同一个坑，该 store 本轮已随死链路删除）。

### 1.2 备份/恢复链路（`9cb57ed`）

三个互相叠加的缺陷：
1. **备份丢列**：`backup-repository.ts` 的 TABLE_SCHEMAS 是手写列清单，011/013/014 三个迁移新增的 `execution_errors_json / sort_order / fingerprint` 没同步进去 → 备份→恢复后这些列的数据**静默丢失**。已补齐 3 列。
2. **恢复旧备份变砖**：`schema_migrations` 表本身也在备份清单里，恢复旧备份会把迁移记录打回旧版本 → 下次启动重复执行 `ALTER TABLE ADD COLUMN`（非幂等）→ 数据库错误态。现在 `replaceAll()` 跳过 `schema_migrations`（恢复数据、保留当前迁移进度）。
3. **迁移前自动备份版本误标**：`bootstrap.ts` 把 dump 时的 `schemaVersion` 写死为 LATEST（此时数据其实还是旧结构）——用它恢复正好触发第 2 条。现在从 `schema_migrations` 读真实 `MAX(version)`。

**守护测试**：新增 `backup-schema-guard.test.ts`——用 `PRAGMA table_info` 双向校验备份列集合与物理表结构一致。**今后任何迁移加列，这个测试会拦住你**：要么同步更新 TABLE_SCHEMAS，要么把列写进测试里的 `EXCLUDED_COLUMNS` 并注释原因。

### 1.3 分享/通知通道（`18a6a22`）

| 缺陷 | 改法 |
|---|---|
| 文字分享记账**必然失败**：主线程同步写 Room（未开 allowMainThreadQueries），异常被吞但 Toast 显示成功 | `writeCaptured` 移入 executor，按真实结果 Toast；executor 补 onDestroy shutdown |
| minSdk=24 用 `java.time.Instant` → Android 7.x 必崩 | 新增 `CapturedPaymentInfo.nowUtcIso()`（SimpleDateFormat UTC，API 24 兼容） |
| 通知/分享指纹掺 `UUID.randomUUID()`/`randomToken()` → **持久去重层完全失效** | 指纹改为 `pkg:method:amount:merchant:分钟桶`（同一笔支付 1 分钟窗口内一致） |
| 连带发现：通知通道 `occurredAt` 写 epoch 毫秒字符串，前端当 ISO 解析必得 Invalid Date | 三通道统一写 UTC ISO（`nowUtcIso()`） |
| "48.50 元"格式金额永远解析不出（正则第二分支无捕获组，`group(1)` 为 null） | 5 个适配器正则补第二捕获组，提取 `group(1) ?? group(2)` |
| 去重"先标记后落库"，写失败 2 分钟内不能重试 | `CaptureDedup` 拆出 `hasSeen`/`markSeen` 对；通知/分享链路落库成功后才标记。**无障碍链路保留 `isDuplicate`（检查+标记，行为未变）** |

### 1.4 前端数据层与行为批（`01ae794`）

- **P1-7 编辑保留溯源字段**：编辑 = void 旧交易 + 插新交易，原来新交易不带 `fingerprint/import_batch_id/capture_source/...` → 导入批次撤销漏掉已编辑交易、防重指纹丢失。现在 `editTransactionFull` 在 replace 前从旧交易继承这 5 个字段（`TransactionDraft/StoredTransaction` 补了 `importBatchId`，INSERT 补了列）。
- **P1-6a PIN 加固**：单轮 SHA-256 → **PBKDF2-SHA256 21 万轮**。存储格式 `pbkdf2$<iterations>$<salt>$<hash>`；**旧格式哈希在验证成功后透明升级**，用户无感。`changePin`/`setupPin` 走新格式。
- **P1-6b 备份排除应用锁凭据**：`app_lock_*` 三键不进备份 JSON（备份落公共 Documents 目录，凭据随包可被离线爆破）。**恢复后应用锁是关闭状态，需重设 PIN**——这是有意的设计取舍，不是 bug。
- P2 批：删全局 `* box-shadow` 调试样式（**视觉会恢复设计稿的阴影，需肉眼确认**）；诊断轮询补 `onDeactivated` 停止；`yearRange` 改本地时区年界；`formatMinorToCny` 支持负数；图片读取失败捕获提示；doConfirm 600ms 延迟清理校验 current 未被覆盖；剪贴板"暂不导入"补写指纹缓存；路由补 404 兜底。
- **015 迁移**：`transactions.fingerprint` 部分索引（014 的列一直没有索引，查重查询会全表扫）。`LATEST_SCHEMA_VERSION` 现在 = 15，相关测试期望已同步。

### 1.5 Android 安全批（`feaa566`）

- **P1-3 Shizuku 假成功**：`ShizukuShell.exec` 失败原来返回 `""`，调用方 `result != null` 恒真——冷启动（UserService 异步绑定未完成）时"恢复成功"全是假象。现在失败返回 **null**；`tryEnable` 判空 + put 后**回读 settings 确认真实生效**。

- **P2-18**：specialUse 前台服务补 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` property。
- **P2-20**：accessibility_config.xml 移除 `flagReportViewIds`（小米澎湃 OS 上注册期即 SecurityException，与代码里的运行时降级策略矛盾——XML 先于代码生效）。

## 3. 真机回归清单（发版前必测，按优先级）

> 全部改动都过了编译/单测/构建，但以下行为只能在真机上确认。建议用 Android 15 真机 + 一台 Android 7/8 设备（验 P0-5）。

1. **自动记账全链路**（最重要）：支付宝/微信真实支付 → 捕获 → 待确认列表出现 → 点确认 → **入账成功且金额/分类/方向正确** → 指纹 confirmed → 同一笔不再重复捕获。
2. **收入捕获**：收红包 → 待确认列表 → 确认弹窗显示**收入分类池** → 确认后是**收入**不是支出。
3. **转账捕获**：转账/提现 → 确认弹窗"去记账" → 完整记账页预填转账模式 → 保存。
4. **在记账页时的新捕获**：正在手动记账时来一笔支付 → 回 APP → 记账页不跳转、待确认列表有记录。
5. **文字分享**：分享文本到"私人记账-记账" → Toast 成功 → APP 内出现待确认（**Android 7.x 设备重点测**，原 java.time 必崩）。
6. **通知捕获**：支付后不打开 APP → 通知 → 捕获 → occurredAt 是合法日期。
7. **备份→恢复**：设置里备份 → 恢复 → 交易/分类/余额完整、**账户拖拽排序保留**、`fingerprint` 列有值（可进 SQL 查）→ **恢复后不砖、能正常启动**。注意恢复后应用锁关闭（设计如此）。
8. **PIN**：老版本升级场景——旧 PIN 能解锁且无感升级（此后 app_settings 里 pin_hash 变成 `pbkdf2$210000$...`）→ 设置新 PIN/改 PIN 正常。
9. **Shizuku**：冷启动即开 APP → 自动恢复无障碍 → 健康页显示真实状态（原来会假成功）；手动在系统设置关闭无障碍 → 恢复动作是否仍被触发（**daemon 强制恢复问题未修**，见 §4-2，行为与之前一致）。
10. **保活**：app 进入后台 5 分钟 → 无障碍服务不断开（specialUse FGS + property 生效）。
11. **视觉**：全应用阴影恢复（删了全局 box-shadow 覆盖），对照设计稿确认没有哪里异常。
12. **诊断轮询**：离开自动记账设置页 → logcat 里诊断接口调用停止。
13. **悬浮窗权限设置**：设置页的权限检查与跳转仍正常（链路删了但权限引导保留）。

## 4. 遗留事项（本轮有意未做，接手人注意）

1. **P1-1 无障碍服务类名伪装**（`com.google.android.accessibility.selecttospeak.SelectToSpeakService`）——**产品/渠道决策，不能由代码单方面改**：
   - 上 Google Play → 必须改名（Play"冒充"政策硬命中），改名后可开 R8（`-keep` 服务类名），顺带解决 release 日志剥离与 APK 体积；
   - 仅侧载 → 保留现状，接受微信对抗升级风险。
   - **未决策前 minifyEnabled 保持 false、proguard 保持空模板（现状未动）。**
2. **P1-2 Shizuku daemon 每 30 秒无视开关强制恢复无障碍**（`shizuku/user/UserService.java` 的 30s 循环）：daemon 跑在 shell 权限进程，读不到应用侧开关；修复需要跨进程传开关状态（binder 加方法或 rebinding 传参），无法在无真机环境下安全验证，**本轮未动**。建议方案：IShell 增加 `setAutoRestoreEnabled(boolean)`，应用侧开关切换/启动时调用。
3. **PIN 无验证次数限制**：PBKDF2 已提高离线成本，但在线试错无节流。建议加"连续 5 次失败锁 30 秒"（需 UI 配合，涉及 PinUnlockView）。
4. **转账手续费编辑回填**：fee 不是独立列（化在分录里），编辑带手续费的转账保存会丢手续费——彻底修复需要 schema 增加 fee 元数据或从分录反推，本轮只做了 API 透传准备（`EditTransactionFullInput.feeMinor/feeCategoryId` 已加，createTransfer 会用）。**RecordSheet 编辑入口未传 fee**（因为读不回来）。
5. **014 指纹的查询方**：索引已建（015），但**没有代码在写库前用 `WHERE fingerprint = ?` 查重**——查重仍靠 Android 端 capture_fingerprint 表 + DuplicateBlocker。若要做"账单自携带指纹兜底查重"（014 注释的意图），需要在前端 createExpense/createIncome 前或 native 侧补查询。
6. **xlsx@0.18.5** 两个未修复 CVE（导入文件来自用户本人，风险可控）——建议加导入大小限制或换 SheetJS CDN 版。
7. **`String.format("%.2f")` 未指定 Locale**（DetailPageParser:140）——土耳其语等区域会输出 "48,50"，下游截断成 48 分。一行改动，等适配器回归时一起做。
8. **冗余收敛**（三套确认 UI→1 组件、5 份聚合 SQL→1 视图、应收/应付仓库合并、RecordSheet 2040 行拆分）——纯重构，方案在整改方案 §2，建议发版后做。
9. **性能优化**（无障碍主线程 8 轮扫描/正则缓存/packageNames 白名单、getTransaction N+1、导入批量化）——方案在整改方案 §5，发版后做。

## 5. 快速上下文备忘（踩坑记录）

- **异步上下文拿不到 inject()**：一切在 store action / 事件回调里需要 FinanceService 的地方，用 `window.__financeService ?? appStore.financeService`。
- **三通道时间格式统一为 UTC ISO**（`CapturedPaymentInfo.nowUtcIso()`）——别再写 epoch 毫秒字符串或 java.time（minSdk 24）。
- **指纹格式**：`pkg:method:amount:merchant:分钟桶` / `order:单号` / `tx:hash`。**任何位置都不要再掺 UUID/Random**——持久去重会失效。
- **备份 schema 是双头维护**：迁移加列必须同步 TABLE_SCHEMAS（有守护测试兜底）。
- **schema 版本 = 15**；迁移测试里的版本数组要跟着加（本次踩过：有多处硬编码数组）。
- **本地插件条目**：`cap sync` 会冲掉 `capacitor.plugins.json` 里的 ClipboardReaderPlugin/PaymentCapturePlugin，`npm run cap:sync` 已自动重打补丁，别裸跑 `npx cap sync`。
- **Gradle 构建**：本机命令行需 `JAVA_HOME="/c/Program Files/Android/Android Studio/jbr" ./gradlew ...`（JAVA_HOME 未配置）。
