## 1. 存在的问题：怎么改

### 1.1 阻塞发布的功能缺陷（P0，估计 1~2 天全部修完）

#### P0-1 「确认入账」三条路径必然失败 ⭐最优先
**现象**：无障碍捕获 → 待确认列表 → 点"确认入账"必抛"账务服务不可用"；当场弹窗、悬浮窗提交同样必失败。
**根因**：`capture-inbox-service.ts:40` 在异步上下文调用 `useFinanceService()`，而它内部是 Vue 的 `inject()`——只能在 setup 同步栈使用，此处恒返回 `undefined`。
**改法**（约 3 行，main.ts:77-78 已有现成全局兜底）：

```ts
// capture-inbox-service.ts confirmEvent() 开头
const appStore = useAppStore()
const finance = (window as any).__financeService ?? appStore.financeService
```

**回归测试**：真机走一遍"捕获 → 待确认列表 → 确认"和"当场弹窗 → 确认"。

#### P0-2 收红包/转账方向确认后被记成支出
**现象**：`confirmEvent` 硬编码 `createExpense`，事件里的 `direction` 字段被丢弃。
**改法**：按方向分派；transfer 方向需要目标账户，短期方案是强制跳转完整记账页（数据已带好）：

```ts
if (input.event.direction === 'income') {
  const id = await finance.createIncome({ ...同参数, categoryId: 收入分类 })
  ...
} else if (input.event.direction === 'transfer') {
  // 无目标账户 UI，跳转记账页：router.push({ path:'/transactions/new', query:{...} })
} else {
  const id = await finance.createExpense({ ... })  // 现有逻辑
}
```
**长期**：确认弹窗按 direction 切换分类池与字段（收入分类池 / 转账目标账户选择）。

#### P0-3 入账成功后队列清理失败 → 误报失败 → 重复入账
**根因**：`capture-inbox-service.ts:62` 的 `acknowledgeEvents` 无 try-catch，抛错会让 UI 把"已入账"当"失败"展示。
**改法**：

```ts
try {
  await PaymentCapture.acknowledgeEvents({ ids: [input.event.id] })
} catch (e) {
  logger.warn('入账成功但队列清理失败（不影响入账结果）', e)  // 账已入，绝不能向上抛
}
```

#### P0-4 文字分享记账整条链路必然失败
**根因**：`PaymentShareActivity.handleTextShare()` 在主线程同步调 Room `insert()`（未开 allowMainThreadQueries），异常被 catch 吞掉，但 Toast 已显示"已识别成功"；且 `CaptureDedup` 在插入前就标记 key，2 分钟内重试也被拦。
**改法**：与图片分支一致，全部移入 executor：

```java
executor.execute(() -> {
    boolean ok = writeCaptured(info, "share_text", "分享文本");
    runOnUiThread(() -> {
        Toast.makeText(this, ok ? "已识别到支付信息" : "识别失败，请重试", Toast.LENGTH_SHORT).show();
        finish();
    });
});
```
同时把 `CaptureDedup.isDuplicate` 的"先标记后落库"改为"落库成功后再标记"（连带修 P2-26）。

#### P0-5 Android 7.x 设备崩溃
**根因**：`PaymentShareActivity.java:230` 用 `java.time.Instant`（API 26+），而 minSdk=24 且未开脱糖。
**改法**：`entity.setOccurredAt(String.valueOf(System.currentTimeMillis()))`（与通知/无障碍链路的时间格式一致，改动最小）。

#### P0-6 通知/分享通道的去重指纹完全失效
**根因**：两处指纹掺入随机数——`PaymentNotificationListenerService.java:169` 的 `UUID.randomUUID().substring(0,8)`、`PaymentShareActivity.java:254` 的 `randomToken()`。同一笔支付每次指纹都不同，`capture_fingerprint` 表对这两条通道形同虚设。
**改法**：去掉随机尾巴，换成可重现的指纹（与无障碍链路对齐）：

```java
// pkg:method:amount:merchant:分钟桶 —— 同一笔支付 1 分钟窗口内指纹一致
return rawPkg + ":" + method + ":" + rawAmt + ":" + rawMerchant + ":"
     + (System.currentTimeMillis() / 60000);
```

#### P0-7/8/9 备份与恢复三连（一次改完）
| # | 根因 | 改法 |
|---|---|---|
| P0-7 | `backup-repository.ts` 的 TABLE_SCHEMAS 漏了 011/013/014 新增的 3 列（`execution_errors_json`、`sort_order`、`fingerprint`），恢复后静默丢列 | 补齐 3 列；**并新增一个守护测试**：用 `PRAGMA table_info` 对比每个表的物理列与 TABLE_SCHEMAS，杜绝以后迁移与备份 schema 双头维护再漂移 |
| P0-8 | 恢复旧备份时 `replaceAll` 会把备份里的 `schema_migrations` 旧记录覆盖进当前库 → 下次启动重复执行非幂等迁移（`ALTER TABLE ADD COLUMN` 报 duplicate column）→ 应用进入错误态"变砖" | `replaceAll` 跳过 `schema_migrations` 表（恢复数据、保留当前迁移进度）；恢复完成后校验物理 schema 与迁移记录一致 |
| P0-9 | `bootstrap.ts:125` 迁移前自动备份把 `schemaVersion` 写死为 `LATEST_SCHEMA_VERSION`，此时数据其实还是旧版本；用它恢复正好触发 P0-8 | 从 `schema_migrations` 读 dump 时刻的真实 max 版本号写入备份 |

**回归测试**（现有测试恰好全部绕开了这三个坑，必须补）：
1. v12 备份 → 在 v14 库上恢复 → 应用可正常启动、迁移记录仍是 1..14；
2. v14 备份 → 恢复 → `fingerprint/sort_order/execution_errors_json` 三列数据仍在；
3. 迁移 013 成功 014 失败 → 用迁移前备份恢复 → 不砖。

### 1.3 一般缺陷（P2，发布后第一个迭代修完）

关键项（完整 31 项见审查报告 §二）：

- **KeepAlive 生命周期**：`CaptureSettingsView` 的 2 秒诊断轮询离开页面后永不停（只挂了 onUnmounted，App.vue 用 `<KeepAlive :max="32">` 缓存所有页面）→ 改 `onDeactivated` 停 / `onActivated` 启。RecordSheet 恰好做对了，照抄它的模式。
- **全局样式污染**：`DeleteVerifyPopup.vue:202` 的 `* { box-shadow: none !important }`（无 scoped）从启动起杀掉全应用阴影 → 直接删。
- **统计口径**：年度统计用 UTC 年界、月度用本地月界，UTC+8 下元旦 0-8 点两边归属不同年份 → `yearRange` 改本地。
- **负数金额格式化**：`formatMinorToCny(-50)` 输出 `-1.-50` → 先取绝对值再加符号。
- **编辑丢手续费**：RecordSheet 编辑回填缺 `feeMinor` → 编辑带手续费转账保存即抹平。
- **`/capture-quick` 断链**：原生注入 `location.hash` 但路由是 history 模式，从未生效 → 随 §2.1 死链路一并处理。
- **无 404 兜底**：加 `{ path: '/:pathMatch(.*)*', redirect: '/' }`。
- **队列表无界增长**：`markExpired` 无人调用，acknowledged 记录永不清理 → 启动时清理 7 天前非 pending 记录。
- **Android 15（targetSdk=36）**：specialUse 前台服务缺 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` property → 补上；真机回归无障碍+悬浮窗链路。
- **`xlsx@0.18.5`** 有两个未修复 CVE（导入文件来自用户本人，风险可控）→ 加导入大小限制，中期换 SheetJS CDN 版。
