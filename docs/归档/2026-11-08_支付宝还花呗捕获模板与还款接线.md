## 四、范围
**做什么：**
1. 新模板 `alipay-huabei-repayment`（支付宝·还花呗），前端 TS 默认规则 + 原生 Java 默认规则各一份，配置版本 5→6：
   - pageSignature：requireAll ["还款成功","花呗"]（还花呗专属，不与还信用卡页抢）；requiredAnyLabel ["创建时间","支付时间","还款时间"]；requireAnyOf ["还款到","付款方式"]
   - fieldAliases：occurredAtLabel ["创建时间","支付时间","还款时间"]、accountLabel ["付款方式","支付方式"]（转出账户线索）
   - directionRule：selfTransferFields ["还款到","付款方式"] → transfer；default "transfer"
   - defaultTargetAccountHint "花呗"（模板语义固定转入方，同微信零钱通转出/提现模板既有做法；用户换账户名时改规则）
   - priority 210（高于通用账单详情 200）；categoryMappings 空（还款不需要分类）
2. RecordSheet 预填接线（约 15 行）：捕获方向为 transfer 时，先用转入线索匹配**信贷账户**，命中 → `switchMode('repayment')`（复用现有还款模式与 createRepayment 入账），转入预填该账户；未命中 → 维持现有 transfer 行为。转出账户预填走现有 accountHint 匹配（中信银行储蓄卡(5441) 有尾缀强匹配）。
3. 顺带修复 TS/Java 默认规则漂移：把原生已有、前端漏掉的 `wechat-transfer-in`（微信·转账收入，p205）补进前端 DEFAULT_RULES（含 CaptureRule 接口补 `defaultCategoryId?: string` 字段），防止下次前端保存默认配置时把该规则冲掉。
**明确不做什么：**
- 不动任何入账/去重/解析器代码（DetailPageParser、createRepayment、指纹链路全部原样复用）
- 不做「还款成功」结果页捕获（只做账单详情，与用户实际使用路径一致）
- 不做还信用卡模板（等有读屏数据再做）
- 不清理待确认队列数据（id 82 由用户自己点忽略）
