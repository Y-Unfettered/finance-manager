## 一、任务名称
到期提醒增强：按月循环 + 首页开 APP 弹窗提醒（"今日不再提醒"）。

## 二、需求沟通记录
- 提出时间：2026-11-08
- 我的理解：用户测试"到期提醒"后确认现状只是登记簿（无主动提醒、无循环、advanceDays 存而不用），提出需求：①打开 APP 时首页弹窗提醒，弹窗卡片带"今日不再提醒"勾选（勾后当天不再弹，次日仍在提醒时间段则再弹）；②保留现有"提前 N 天提醒"设置；③新增按月循环（信贷还款日每月固定日期自动重复，相当于模板），无需每月手动重设。
- 现状核查（代码为准）：reminders 表为一次性固定日期（迁移 008）；无循环字段；App.vue/首页无提醒展示；advanceDays 无消费方；无本地通知能力。
- 用户确认：☐ 待确认（本文件）

## 三、目标
信贷账户（花呗/白条/美团月付等）设一次"每月 X 号还款"提醒后：每月自动进入提醒窗口，打开 APP 首页弹窗提示，勾"今日不再提醒"当天安静、次日再弹；点"标记已处理"当期不再弹、下期照常。不循环提醒保持原行为。

## 四、范围
**做什么：**
1. 数据模型（迁移 020）：reminders 表加 `recurrence` 列（TEXT，'none'|'monthly'，默认 'none'）；同步 `backup-repository` 的 TABLE_SCHEMAS（项目已知坑）；领域类型补字段。
2. 循环语义（reminder-service 核心，纯函数可测）：
   - monthly：以 dueDate 的"日"为锚，每月同日为下一到期日（31 号等超月末时取当月最后一天）；不早于存储 dueDate（锚点之前不产生虚拟期次）。
   - listUpcoming 改为按"下一到期日"计算：daysUntilDue、窗口判断都用下一到期日；repo 查询放宽（取 enabled 全量，计算在 service 层），列表窗口仍 30 天。
   - 提醒窗口 = [下一到期日 − advanceDays, 下一到期日]。
   - "标记已处理"：循环提醒处理当前期——lastTriggeredAt 落在本期窗口内即视为已处理（本期不再弹窗、列表显示已处理角标），下期照常。
   - 不循环且已过期的项：近期到期列表显示"已过期 X 天"（启用现成 overdue 样式），不再凭空消失。
3. 编辑页（RemindersView）：
   - 表单加"每月同日重复"开关（存 recurrence）；编辑循环提醒时日期字段提示"按每月同一天自动延续"。
   - 近期到期列表：循环项显示"每月重复"角标 + 下一到期日；已处理角标；过期项显示已过期天数。
4. 首页弹窗（HomeView）：
   - 时机：打开 APP 进入首页时 + 从后台切回 APP 时；每天弹过且勾选"今日不再提醒"则当天静默。
   - 内容：处于提醒窗口内且当期未处理的所有提醒，一条卡片列出（标题/类型/账户/下一到期日/X 天后到期或今天到期/金额），底部勾选"今日不再提醒"+「知道了」按钮。
   - "今日不再提醒"为整包当天生效（localStorage 记当天日期，次日自动失效）。
**明确不做什么：**
- 不做系统推送通知（@capacitor/local-notifications）——本轮仅应用内弹窗；需要时下轮立项。
- 不做每条提醒单独的"今日不再"（按用户描述整包生效）。
- 不动"模板与周期交易"功能（recurring_transactions 是另一套，互不影响）。
- 不改备份/恢复以外的原生代码。

## 十、用户反馈 / 追加轮次
- 2026-11-08（第 1 轮实测反馈）：首页弹窗效果认可；**到期提醒页卡片之间的间距不符合现有 UI，全部贴死**。
  - 根因：`.section` 只给了 `h2` 一个 margin，卡片（`BaseCard`）之间没有任何栈间距，两张卡边框直接相接；"近期到期""全部提醒"两个区块同款。
  - 修法：按项目既有卡片栈约定（`ImportBatchesView.batch-section`）——`.section { display:grid; min-width:0; gap: var(--space-3) }`（卡片 12px），标题 `margin: var(--space-2) 0 var(--space-1)`；内容区 section 间沿用 `gap: var(--space-4)`。纯 CSS，无逻辑改动。
  - 已验证：包内 `RemindersView-*.css` 含 `section[data-v-5d9d87dc]{gap:var(--space-3);min-width:0;display:grid}`。
  - 顺带发现（未修，待用户拍板）：`TemplatesView`（模板与周期交易）的 `.section` 同样没有卡片栈间距规则，卡片也贴死；且其 `openEditRecurring` 的 `endDate.slice(0,10)` 对 UTC ISO 会取到前一天。
- 2026-11-08（第 2 轮实测反馈）：编辑提醒（"花呗还款"）打开"每月同日重复"后保存，弹英文报错 **`invalid time value`**。
  - 查实结论：不是缺时间参数，也不是循环开关的问题，是 **`Date.prototype.toISOString()` 对 Invalid Date 抛的原生 `RangeError: Invalid time value`**。
  - 触发链：`openEdit` 把库里的完整 ISO（本地 11-08 零点 → `2026-11-07T16:00:00.000Z`）原样塞进 `form.dueDate`；`submit` 又拼一次 `` `${form.dueDate}T00:00:00` `` → `2026-11-07T16:00:00.000ZT00:00:00` → Invalid Date → `toISOString()` 抛错。新建提醒（表单是 `YYYY-MM-DD`）不触发，所以只在"编辑已有的那条"时冒出来。
  - 修法：新增 `features/reminders/reminder-dates.ts`——`toDateInputValue()`（ISO → 表单 `YYYY-MM-DD`，按本地日期字段取，编辑时归一化）、`dateInputToLocalIso()`（表单日期 → 本地零点 ISO，纯日期按分量构造不吃时区，非法抛中文"到期日期格式不正确"，不再放 RangeError 出来）；`submit` 改用它，删掉本地 `localDateValue`。
  - 顺带修：表单错误原来复用页面级 `errorMessage`，保存失败会把整个列表替换成红字错误页 → 拆出 `formError`（只红字提示、列表照常），失败时写 `getLogger('reminder')` 日志，可从「设置→日志」查。
  - 验证：`reminder-dates.test.ts` 6 例（本地日期还原/纯日期往返/非法日拒收/不再抛 RangeError），TZ=Asia/Shanghai 下单独复核通过；vue-tsc 通过、vitest 40 文件 / 298 用例全过；重打包 19:42 并反解 APK 确认旧拼接写法已消失。
  - 说明：真机日志未取到（本机无 adb、项目无日志导出文件），结论由纯函数复现代替。
