## 三、目标
全应用卡片内容与边框保持安全边距；新增「匹配规则」两级页面（应用列表 → 应用内模板列表），数据实时取自生效规则。

## 四、范围
**做什么：**
1. SettingsView：`.settings-card` 上下内边距 0 → `var(--space-2)`（拆开与 entry-card 共用的选择器，entry-card 行式布局不动）；`.reader-entry` 补与上方开关的间距。
2. 新增路由与页面：
   - `/settings/capture-rules`「匹配规则」列表页：规则按 packageName 分组（支付宝/微信/京东/美团/抖音），每应用一张卡（名称、模板数、启用数），点击进入详情。
   - `/settings/capture-rules/:packageId` 应用模板页：该应用全部模板（规则），每条展示：模板名、pageType 标签（账单详情/成功页）、priority、启用徽章、页面特征词（requireAll/requiredAnyLabel/requireAnyOf）、备注来源字段、金额字段；页头显示规则集版本号。
   - 数据源 `loadRuleConfig()`（原生 getCaptureRules，动态）；规则加载失败显示错误态。
3. 入口：SettingsView「诊断」区加「匹配规则」入口；自动记账设置页顶部加入口按钮（就近原则）。
4. 白名单外包名的规则（如有）按同样分组逻辑自然展示。
**明确不做什么：**
- 不做规则编辑/新增/删除 UI（本期纯只读）
- 不做模板字段全量展开（fieldAliases 逐项列出等留后续，本期展示摘要）
- 不改规则数据结构与原生接口

### 实施补充（2026-11-06）
- **边界说明**：详情页 URL 含包名点号（如 /capture-rules/com.eg.android.AlipayGphone），Capacitor 本地服务器会把多段点号当文件扩展名拒绝整页加载（net::ERR_INVALID_RESPONSE）——**用户正常使用（列表 router 内部导航）不受影响**，仅"整页刷新深链接"这一非用户路径受限；验证时须用 router/点击导航。
- 顺手修：tokens.css 补 `--color-success`（channel-status/模板徽章此前引用了未定义变量，绿药丸一直没显示颜色）。

### 用户反馈（2026-11-06 第二轮）
- 用户报告：①列表显示微信 5 个模板，**点进去却全是"抖音"的东西**（成功页/成功词），看不到专门的详细模板 → 根因：**KeepAlive 复用同组件实例**，详情页只在 onMounted 读一次路由参数，点不同应用时 params 变化但页面复用了首个应用的缓存数据。已修：`watch(route.params.pkg)` 参数变化即重载。②用户要更详细的模板内容 → 模板卡已增"字段来源"组（金额字段/账户字段/订单号字段，取自 fieldAliases），加上原有的页面特征词组与备注来源，微信账单详情等专门模板的细节均可见。
- 说明：抖音/京东/美团三个应用当前只有"成功页"模板且默认禁用（v5 设计：成功页不可靠已停用），所以内容天然较少；**详细模板集中在微信/支付宝的账单详情规则里**。
