到期提醒页三处体验修复：刷新不置顶 + "标记已处理"按"期"判定 + 删除抽屉紧凑化。

## 二、需求沟通记录
- 提出时间：2026-11-08
- 我的理解（用户原话归纳）：
  1. 在"近期到期"点"标记已处理"，以及在"全部提醒"里点"修改"保存后，**整页会滚回顶部**，用户得重新往下滚才能回到刚才的位置。刷新可以有，但不该把页面置顶——要"记住上一个页面的状态"。
  2. 还有 7 天到期的"抖音月付还款"点"标记已处理"**没有任何反应**；而"花呗还款"点了会显示"本期已处理"。怀疑其他条目也有同样问题。
  3. 删除提醒的确认抽屉里，"取消"和"删除"两个按钮下方留白太大；希望两个按钮稍微放大、一横排放置，并让抽屉高度贴合内容。
- 诊断结论（已核对代码）：
  1. 置顶 = `load()` 每次都把 `loading` 置 true，模板里两个列表是 `v-if="!loading"`，列表被整段拆掉 → 内容高度塌回 0，滚动容器 `scrollTop` 被钳到 0 → 数据回来停在顶部。`onActivated` 里那次刷新也会把 `RoutePageFrame` 刚恢复的滚动位置打掉。
  2. 无反应 = `isHandledInCurrentPeriod()` 要求"今天落在 [到期日−提前天数, 到期日] 窗口内"才算已处理。抖音月付剩 7 天、提前天数默认 3 → 不在窗口 → 写了库但仍判"未处理"，按钮不消失也没有"本期已处理"。花呗在窗口内所以正常。凡是"距到期日 > 提前天数"的条目都点不动。
  3. 抽屉空隙 = `AppBottomSheet` 全局 `min-height: 240px`，删除确认内容很短，多余高度全成了按钮下方空白。
- 建议方案（已与用户敲定）：
  1. 静默刷新：只有首次进入 / 手动点"重新加载"才显示 loading 骨架；标记已处理、保存编辑、切换启用、删除、`onActivated` 回页一律静默刷新，数据原位替换，不塌高度、不动滚动。
  2. "标记已处理"改按"期"判定：`lastTriggeredAt` 落在本期（上一期到期日之后、本期到期日之前或当天]即算本期已处理；跨期自动恢复。首页到期弹窗同步生效（本期处理过就不再重复弹）。
  3. 删除抽屉（第二轮反馈细化）：不删除抽屉，只改面板形态——高度随内容收缩（不留空白），"取消/删除"两个按钮**钉在面板最底部、从下往上排**，五五等宽、铺满可用宽度并留左右安全距离，按钮放大（48px 高 / 15px 字）。
- 用户确认：☑ 已确认（2026-11-08，三个决策点已拍板：整页回顶 / 按"期"判定且弹窗同步 / 只改提醒页删除抽屉）
- 第二轮追加（2026-11-08）：
  - 明确"删除"指"全部提醒"里那条删除按钮召唤的面板，不是要删掉抽屉功能。
  - 面板问题是"两个按钮离屏幕底部太远、空了很多"，诉求 = 按钮贴屏幕最底部、五五等宽、四周留安全距离。
  - 明确**不要"撤销已处理"功能**：还款提醒看到就还、还完点一下即可，不存在"点了又不还还忘掉"的场景。

## 三、目标
1. 提醒页所有数据刷新都**就地更新**：用户点击后停留在原来的滚动位置，不闪 loading、不整页回顶。
2. "近期到期"里任意条目点"标记已处理"都**立即有反馈**（按钮消失 + 显示"本期已处理"），且本期不再在首页弹窗重复提醒；下一期自动恢复。
3. 删除确认抽屉高度贴合内容，"取消/删除"两个按钮钉在面板最底部、一横排五五等宽、更好点，按钮下方不再有大片空白。

## 四、范围
**做什么：**

1. `app/src/views/RemindersView.vue`
   - `load()` 增加静默模式（`load({ silent: true })`）：静默时不动 `loading`，直接用新数据替换现有列表。
   - 调用方调整：`markTriggered`、`submit`（编辑保存）、`toggleEnabled`、`confirmDelete`、`onActivated` 改静默刷新；`onMounted` 与错误态下的"重新加载"按钮保留骨架 loading。
   - 删除抽屉：`<AppBottomSheet :min-height="0">`（紧凑高度）；`.confirm-dialog` 改 grid 紧凑布局；按钮行改为 `.confirm-actions` 两等宽按钮（取消=描边、删除=实心 `--color-expense` + 加粗），`min-height: 48px`、字号 15px，贴在面板最底部；左右 16px 留白来自抽屉 body padding，底部安全距离由 Popup 的 `safe-area-inset-bottom` + body padding 兜住。
2. `app/src/components/AppBottomSheet.vue`
   - 新增可选 prop `minHeight`（number，默认 240），以 `:style` 形式作用在弹层根节点；默认值保证其余 8 处调用视觉完全不变。
3. `app/src/features/reminders/reminder-service.ts`
   - `isHandledInCurrentPeriod()` 改为按"期"判定（不再依赖 `isInReminderWindow` / `advanceDays`）：
     - 一次性提醒：`lastTriggeredAt` 本地日期 ≤ 本期到期日 → 已处理。
     - monthly：另需 `lastTriggeredAt` 本地日期 > 上一期到期日（上一期 = 本期到期日往前一个月、按锚点日 clamp 短月）。
     - `lastTriggeredAt` 晚于本期到期日（改期/时钟异常）→ 未处理。
   - 新增内部纯函数 `previousDueOccurrence()` 计算上一期到期日。
   - `isInReminderWindow()` 保留（首页弹窗仍用它做窗口过滤）。
4. `app/src/features/reminders/reminder-service.test.ts`
   - 更新 `isHandledInCurrentPeriod` 用例（窗口外标记 → 已处理；上一期标记 → 未处理；一次性提醒 → 已处理）。
   - 更新"标记已处理后当期 isHandled=true"用例：去掉"先把到期日改到窗口内"的绕坑写法，直接用剩 8 天的提醒验证。

## 七、风险点 / 待决策
- **语义变化**：提前很久标记已处理 → 本期彻底不再提醒（含首页弹窗）。若用户提前处理后又需要提醒，只能等下一期；**按用户要求不做"撤销已处理"**。
- **滚动位置**：静默刷新若数据变少（如删除条目），原滚动位置可能超出新内容高度，浏览器会自动钳制到能显示的位置——属正常表现，不额外补偿。
- **重复点击**：静默刷新期间数据未回，用户可能再点一次；已有 `saving` 守卫，不会重复提交。
- **改期边界**：monthly 提醒改到期日后，`lastTriggeredAt` 可能落到新一期的区间内而被判"已处理"。属可接受，必要时后续加"改期清标记"（`updateReminder` 已预留 `lastTriggeredAt: null` 能力，本次不动）。
- **AppBottomSheet 影响面**：新增 prop 必须带默认值 240，否则其余 8 处调用会一起变矮。
