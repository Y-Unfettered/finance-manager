# 自动记账 · 捕获规则配置指南

- 文档版本：v1.0（2026-10-31）
- 关联 PRD：《自动记账_账单详情匹配_PRD.md》
- 适用对象：需要为新 APP / 新页面类型扩充识别规则的同事

---

## 1. 核心原则：加页面 = 加 JSON，不改代码

识别引擎（`DetailPageParser.java`）是**通用算法**，不含任何 APP 专属逻辑。
支付宝、微信、京东、美团、拼多多的差异全部体现在**规则 JSON**里。

遇到"某笔账单没被识别 / 识别错了"时，标准处理流程：

```
1. 复现 → 打开 APP「无障碍诊断 → 导出日志」（或 adb logcat）
2. 找 DetailPageParser 日志：
   - "详情签名不匹配(pkg, 规则=xxx): 缺少关键词/标签: XX"  → 页面没进规则，看缺什么特征
   - "详情解析成功: ... note=xx direction=xx"              → 已识别，核对字段对不对
3. 把页面上实际的标签词/状态词补进对应规则的 JSON
4. 保存规则（前端设置页 / saveCaptureRules）→ 原生 10 秒内热生效，无需重装 APP
5. 复测；同时按 §5 在 DetailPageParserTest 补一条该页面的用例
```

## 2. 规则 JSON 字段说明（schema v2/v3）

一条规则 = 一个"页面类型 × APP"的匹配配置：

```jsonc
{
  "id": "alipay-bill-detail",            // 唯一 ID
  "name": "支付宝·账单详情",              // 展示名
  "packageName": "com.eg.android.AlipayGphone", // 按 APP 路由
  "channel": "accessibility",
  "pageType": "bill-detail",             // 缺省 = 成功页规则；bill-detail = 账单详情
  "priority": 200,                       // 同包名同 pageType 下取最大；详情页 200 > 成功页 100
  "enabled": true,

  // ── ① 页面签名：决定"这个页面归不归我管"（防误抓的唯一防线，必须足够严）──
  "pageSignature": {
    "requireAll": ["账单详情"],          // 全部命中（标题等强特征）
    "requiredLabels": ["创建时间"],      // 全部命中（必备结构标签）
    "requireAnyOf": ["交易成功", "转账成功", "收款成功", "付款成功",
                     "付款方式", "转账备注", "对方账户",
                     "提现到", "收款方式", "处理进度"]  // 至少命中一个（状态词/业务字段）
  },

  // ── ② 字段别名：页面标签 → 逻辑字段（同一字段不同 APP 措辞不同，全靠这里映射）──
  "fieldAliases": {
    "amountLabel":     ["实付金额", "实收金额", "金额"],   // 实付金额（有红包/优惠时 ≠ 订单金额）
    "orderAmountLabel": ["订单金额"],                      // 仅用于排除，不会当实付
    "originalPriceLabel": ["原价"],                        // 同上
    "discountLabel":   ["红包", "优惠", "满减", "立减"],   // 同上
    "occurredAtLabel": ["创建时间", "交易时间", "转账时间"],// 时间（ISO/中文自动兼容）
    "accountLabel":    ["付款方式", "支付方式"],            // 账户线索（传给记账页预选账户）
    "merchantLabel":   ["对方账户", "收款方", "商户", "商家"],
    "noteLabel":       ["缴费说明", "交易详情", "转账备注", "商品"],
    "orderIdLabel":    ["订单号", "交易单号", "户号"]       // 指纹最强键
  },

  // ── ③ 备注生成："为什么花" ──
  "noteRule": {
    "preferFields": ["缴费说明", "交易详情", "转账备注", "商品", "理由"], // 按优先级取第一个有意义值
    "cleanPatterns": ["订单编号\\d+$", "App-\\d+$", "[-–]\\d{6,}$"],     // 删除型正则（去尾缀/订单号）
    "maxLength": 50,
    "fallbackToMerchant": true   // 字段全无意义时降级用商户全称（微信京东单场景）
  },

  // ── ④ 方向判定：以字段结构为准，金额符号为辅 ──
  "directionRule": {
    "negative": "expense",                       // 负金额 → 支出（自动）
    "externalIncomeFields": ["对方账户", "转账备注"], // 任一命中 → 收入（外部打款信号）
    "selfTransferFields": ["提现到", "收款方式", "处理进度"], // 命中且无 income 信号 → 转账
    "refundFields": ["退款"],                     // → 退款
    "default": "confirm"                          // 都不命中 → 弹确认
  },

  // ── ⑤ 分类建议：对"备注 + 商户"合并匹配，倒序优先 ──
  "categoryMappings": [
    { "namePattern": "(燃气|水费|电费)", "categoryId": "utilities", "kind": "expense" },
    { "namePattern": "(提现|返现|退款|红包|签到|奖励)", "categoryId": "income-other", "kind": "income" }
  ]
}
```

### 方向判定算法（实现于 `DetailPageParser.decideDirection`，勿在规则里重复）

```
负金额                                   → expense（自动入支出流程）
含 externalIncomeFields 任一字段          → income
含 selfTransferFields 任一（且无上者）    → transfer
含 refundFields                          → refund
其他                                     → confirm（记账页提示用户确认）
```

> ⚠️ 字段选择原则：income 信号必须选**外部打款特有**的字段（"对方账户""转账备注"）。
> "收款方式"同时出现在外部收款页和小荷包转出页，**不能**单独作为 income 信号。

## 3. 新页面校准清单（照做即可）

1. **拿到页面原文**：日志节点树里有全部 `text="..."`；或在 PRD §6 的截图标注。
2. **确认页面类型**：账单详情（支付类 APP）→ `bill-detail`；订单详情（购物类 APP）→ `order-detail`（P2）。
3. **选强签名**：找只有目标页才有的特征（标题"账单详情" + 结构标签"创建时间"）。
   普通页面（首页/列表/动态）必须**一条都凑不齐**——这是不乱弹的保证。
4. **补 fieldAliases**：把页面实际标签词加进对应逻辑字段（不确定就都加上，匹配按行精确匹配标签或"标签：值"）。
5. **补 noteRule.preferFields**：把"为什么花"所在的标签按优先级插入。
6. **补 directionRule**：确认该页的字段结构会落到正确的方向分支。
7. **热生效**：规则存 SharedPreferences，改动经 `saveCaptureRules` 写入后 10 秒内生效；
   改**内置默认规则**（`CaptureRuleDefaults.java` / 前端 `DEFAULT_RULES`）需重装 APP（两处保持同步！）。
8. **补单测**：在 `DetailPageParserTest` 用页面原文补 `extractFields/decideDirection/extractNote` 用例。

## 4. 现状与边界（诚实声明）

| 项 | 状态 |
|---|---|
| 详情页解析（签名/字段/备注/方向/分类） | ✅ 全规则驱动，加页面只改 JSON |
| 规则热更新 | ✅ SharedPreferences + 10 秒缓存 |
| 识别失败定位 | ✅ 日志输出签名失败原因（缺哪个词） |
| 成功页兜底适配器（Alipay/Wechat/Generic） | ⚠️ 代码级正则，已收紧为完整词 + 仅为最后兜底；详情规则覆盖后长期可禁用 |
| 账户预选映射（支付宝→"支付宝/余额宝"） | ⚠️ 前端小映射表；P3 规则编辑 UI 开放 `defaultAccountId` 后由用户配置取代 |
| 分类关键词（提现/返现/奖励…） | ⚠️ 枚举式，新词加进 `categoryMappings` 即可（配置层） |
| 备注尾缀清洗（订单号/App-） | ⚠️ 枚举式，新格式加进 `cleanPatterns`（配置层） |

**判断标准**：凡是"枚举一个词/一条正则"的扩展 → 走配置（JSON），不改代码；
凡是"新的页面类型/新的解析算法" → 才动引擎代码，且必须带单测。
