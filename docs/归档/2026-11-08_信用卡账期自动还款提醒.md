## 一、任务名称
信用卡账期 → 自动生成"每月同日"还款提醒（账户与到期提醒打通）。

## 二、需求沟通记录
- 提出时间：2026-11-08
- 我的理解：创建账户时选"信用卡/信用账户"分类（京东白条、花呗等）会填**出账日**和**还款日**，现在这两个值只存进 `credit_profiles`、只在账户详情页展示，**到期提醒里没有任何条目**。用户要的是：只要建卡时填了出账日 + 还款日，就自动在提醒里生成一条"每月同日"的还款提醒（还款日即提醒日），不用再去提醒页手工加。
- 现状核查（代码为准，2026-11-08）：
  - `credit_profiles` 已有 `bill_day / repayment_day / reminder_days`，创建/编辑账户都会写；`reminder_days`（提前提醒，默认 3）目前只存不用。
  - 提醒侧已有 `credit_card_due` 类型、按月循环（`recurrence='monthly'`，迁移 020，今天刚上线）与首页弹窗；但没有任何"由账期生成提醒"的代码路径。
  - `updateAccount` 对 `reminderDays ?? 3` 直接落值，而账户详情页编辑表单不传该字段 → **每次编辑详情都会把提前天数重置成 3**（既有缺陷，本次一并修）。
- 建议方案（用户已拍板）：
  1. reminders 表加 `managed_by` 标记（值 `credit_profile` = 由信用卡账期自动生成），只有带该标记的条目才被自动同步/停用/删除，不碰用户手工建的提醒。
  2. 建卡即建提醒：出账日 + 还款日都有值 → 生成 `credit_card_due` + `monthly` 提醒，到期日锚到"下一个还款日"，提前天数取账户卡的"提前提醒"，金额留空。
  3. 存量账户一次性回填：升级后首次启动补建（用 `app_settings` 标记只跑一次），之后用户手动删掉不会反弹。
  4. 生命周期：归档 → 提醒停用（恢复账户 → 重新启用）；彻底删除账户 → 自动提醒一并删除；账期被清空 → 自动提醒删除。
- 用户确认：☑ 已确认（2026-11-08，三项决策：一次性补建 / 不带金额 / 归档停用-删除清掉）

## 三、目标
信用卡/信用账户的"还款日"不再是摆设：建卡（或改账期）后，到期提醒列表和首页弹窗里自动出现一条"每月同日"的还款提醒；归档/删卡/清空账期时提醒同步跟着停用或消失，不留孤儿条目。

## 四、范围
**做什么：**
1. **数据模型（迁移 021）**：`reminders` 加 `managed_by TEXT`（可空；`credit_profile` = 信用卡账期自动生成）；`CHECK (managed_by IN ('credit_profile'))`；同步 `backup-repository` 的 `TABLE_SCHEMAS.reminders`（项目已知坑）；`entities` 补 `managedBy?`。
2. **领域纯函数** `features/reminders/credit-repayment.ts`：
   - `nextRepaymentDueDate(repaymentDay, nowIso)`：从今天起算的下一个还款日，返回**本地零点 ISO**（与提醒存库口径一致）；今天正好是还款日则取今天；短月按当月最后一天 clamp（31 号锚点 → 2 月 28/29、4 月 30）。
   - `creditRepaymentReminderTitle(accountName)`：`${账户名}还款`（名字已含"还款"不重复拼接）。
3. **同步服务** `features/reminders/credit-reminder-sync.ts`（`CreditRepaymentReminderService`）：
   - `syncForAccount(...)`：账期齐全 → 建/更新自动提醒；账期缺项 → 删掉自动提醒。
     - 还款日变化 → 重新锚定 `dueDate`；未变化 → 保留现有 `dueDate`（不覆盖用户手工改过的日期）。
     - 提前天数变化 → 同步 `advanceDays`；账户改名且提醒标题仍是旧的自动标题 → 跟着改名（用户改过标题则保留）。
     - 归档 → `enabled=0`；恢复 → `enabled=1`。
   - `removeForAccount(...)`：删账户时清掉自动提醒（同时依赖 FK）。
   - `backfillOnce(...)`：遍历 `credit_profiles`（含已归档账户，建出来即为停用），缺则建、有则不动；`app_settings` 键 `credit_repayment_reminder_backfill` = `v1` 标记，只执行一次。
4. **接线**：`FinanceService` 构造 `CreditRepaymentReminderService`，在 `createAccount / updateAccount / archiveAccount / unarchiveAccount / deleteAccount` 内同步；`main.ts` 启动时（数据库就绪后）触发一次 `backfillOnce`（fire-and-forget，失败只记日志）。
5. **修既有缺陷**：`updateAccount` 的 `reminderDays` 改为 `input.reminderDays ?? existing?.reminderDays ?? 3`，详情页编辑不再把提前天数打回 3。
6. **UI**：提醒列表对 `managedBy='credit_profile'` 的条目加"自动"角标（说明由信用卡账期生成）；其余交互（编辑/删除/开关）照旧。
7. **单测**：还款日锚点（今天/跨月/月末 clamp/闰年）、建卡建提醒、账期变更重锚、清空账期删除、归档停用/恢复启用、删卡清提醒、回填只跑一次、备份恢复带 `managed_by`。

**明确不做什么：**
- 不做系统推送通知（仍为应用内弹窗，沿用它已有能力）。
- 不做"还款金额自动取当前欠款"（用户已选不带金额；`amount_minor` 留空）。
- 不改信用卡账单周期算法（`domain/credit-cycle.ts` 不动，"账期/应还日"计算仍按原逻辑）。
- 不做"提醒到期后自动入账/自动清账"。
- 不动模板与周期交易（`recurring_transactions` 是另一套）。
- 不重构提醒页布局，只加一个"自动"角标。

## 七、风险点 / 待决策
- **提醒重复**：靠 `managed_by` 区分自动/手工，同步只动带标记的；用户手工建的 `credit_card_due` 绑同一账户不会被覆盖。
- **删除后反弹**：回填只跑一次 + 仅在账期值变化时重建；用户在提醒页删掉后，重启不会重建（已按此设计）。
- **时区**：`dueDate` 必须是本地零点 ISO（`new Date(y, m, d)` 构造，禁 `Date.UTC`），否则 UTC+8 下"今天到期"会判错（项目已有前车之鉴：`reminder-dates.ts`）。
- **FK 依赖**：`reminders.account_id` 已是 `ON DELETE CASCADE`，但删账户仍显式清自动提醒，不赌 PRAGMA 是否生效。
- **回填时机**：`main.ts` 里 fire-and-forget，失败只记 `finance` 日志，不阻塞启动；标记写入放在全部账户处理完之后，避免半途失败后永久跳过。
- **备份兼容**：恢复旧备份（无 `managed_by` 列）时按历史加列惯例处理（缺列为空），不额外兼容代码。
- **页面缓存（本轮踩坑）**：`App.vue` 全局 `<KeepAlive>`，列表页若只在 `onMounted` 里加载数据，二次进入会一直显示旧快照。提醒页/任何依赖外部写库结果的列表页，都要用 `onActivated` 重载（本页已修，`skipFirstActivation` 防首次重复）。
- 待决策：是否需要"提醒列表里显示由哪张卡生成"——已用"自动"角标 + 账户名两处兜住，暂不做卡片跳转。
- 后续可查（本轮发现，不在本次范围）：`views/` 下 `AccountsView` 等列表页未用 `onActivated`，若出现"改完数据回列表不更新"，按同一模式修。
