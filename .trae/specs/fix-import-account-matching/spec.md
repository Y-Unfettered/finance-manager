# 导入系统简化重构 Spec

## Why
导入系统过于复杂和专业化了。用户只是改了一个账户名（"美团"→"美团余额"），整个导入就瘫痪了。根本原因是：账户匹配太死板（只认精确匹配）、报错不友好（用户不知道去哪修）、操作流程太专业（"账户映射""CSV中的账户名"等术语用户看不懂）。

## What Changes
- **账户名智能匹配**：精确匹配失败时自动尝试子串匹配，解决"改名后导不进去"的核心问题
- **"映射"步骤去掉**：不再让用户手动填"CSV中的账户名"→"选择账户"，改为预览阶段直接展示"哪些账户没找到，请选择对应关系"
- **指纹从阻断改警告**：相同文件不再直接拒绝，改为提示"这个文件之前导入过，确认继续？"
- **批次记录可靠性**：修复批次不显示、撤销后混乱的问题

## Impact
- Affected specs: 导入系统
- Affected code: `import-service.ts`, `import-types.ts`, `ImportView.vue`, `ImportBatchesView.vue`

## MODIFIED Requirements

### Requirement: 账户名智能匹配
系统在导入时 SHALL 按以下顺序匹配账户名：
1. 精确匹配（名称完全相同）
2. 子串匹配：JSON 中的账户名包含在已有账户名中，或已有账户名包含在 JSON 账户名中，且匹配结果唯一时，自动采用
3. 子串匹配不唯一时，不自动匹配，交给用户在预览阶段手动选择
4. 以上全失败时，标记为"未匹配"，在预览阶段让用户手动处理

#### Scenario: 账户改名后自动匹配
- **GIVEN** 用户将"美团"改名为"美团余额"
- **WHEN** 导入 JSON 中写的是 `sourceAccount: "美团"`
- **THEN** 系统通过子串匹配自动关联到"美团余额"，无需用户干预

#### Scenario: 多个候选时不自动匹配
- **GIVEN** 用户有"美团余额"和"美团月付"两个账户
- **WHEN** 导入 JSON 中写的是 `sourceAccount: "美团"`
- **THEN** 系统不自动匹配，在预览中提示"美团"对应哪个账户，列出两个候选

#### Scenario: 精确匹配优先
- **GIVEN** 用户有"美团"和"美团余额"两个账户
- **WHEN** 导入 JSON 中写的是 `sourceAccount: "美团"`
- **THEN** 精确匹配到"美团"，不走子串匹配

### Requirement: 预览阶段直接修正未匹配项
系统 SHALL 在预览步骤中展示所有需要用户确认的内容：
- 未匹配的账户：显示"「XX」没有找到匹配的账户，请选择："，旁边是下拉列表（列出所有已有账户）+ "创建新账户"按钮
- 未匹配的分类：同上逻辑
- 如果所有账户和分类都自动匹配成功，不显示任何修正区域

#### Scenario: 预览中修正未匹配账户
- **GIVEN** 导入 JSON 中 `sourceAccount: "美团"`，系统找不到精确匹配
- **WHEN** 用户进入预览步骤
- **THEN** 预览顶部显示"'美团'没有找到对应的账户，请选择："，用户从下拉列表中选择"美团余额"，点击"重新检查"后更新

#### Scenario: 全部匹配成功则无干扰
- **GIVEN** 所有账户和分类都自动匹配成功
- **WHEN** 用户进入预览步骤
- **THEN** 只显示交易预览和统计信息，不显示任何账户修正区域

### Requirement: 去掉"映射"步骤，简化流程
系统 SHALL 将导入流程从 4 步简化为 3 步：
- 旧流程：选择文件 → 映射（字段映射+账户映射+分类映射）→ 预览 → 完成
- 新流程：选择文件 → 预览（自动解析+修正未匹配项）→ 完成

字段映射改为自动检测，仅在自动检测失败时提示用户手动调整。

#### Scenario: JSON 导入跳过映射步骤
- **GIVEN** 用户粘贴 JSON 或选择 JSON 文件
- **WHEN** 解析完成后
- **THEN** 直接进入预览步骤，无需经过映射步骤

### Requirement: 指纹警告代替阻断
系统 SHALL 将重复导入的阻断行为改为警告提示：
- 检测到相同指纹的活跃批次时，不阻止导入
- 在预览步骤显示"该文件似乎已经导入过，是否继续？"
- 用户确认后正常导入

#### Scenario: 重复文件不阻断
- **GIVEN** 用户之前导入过同一份 JSON
- **WHEN** 用户修正数据后重新导入
- **THEN** 预览步骤显示警告提示，用户确认后正常导入

### Requirement: 批次记录可靠显示
系统 SHALL 确保批次记录正确显示：
- 所有批次（含执行失败的）都显示在历史中
- 活跃批次和已撤销批次分组显示
- 查询失败不吞错，保留批次记录

#### Scenario: 执行失败的批次显示在历史中
- **GIVEN** 导入批次中有 2 行执行失败
- **WHEN** 用户查看导入批次历史
- **THEN** 该批次正常显示，包含成功/失败计数

## REMOVED Requirements

### Requirement: 独立的"映射"步骤
**Reason**: 用户反馈"CSV中的账户名""选择账户"等术语看不懂，操作复杂
**Migration**: 账户/分类的匹配修正移到预览步骤，用自然语言提示替代专业术语

### Requirement: 手动账户映射（AccountNameMapping）
**Reason**: 用户不需要理解"rawName"和"accountId"的概念
**Migration**: 改为预览步骤中直接展示"未匹配的账户名 → 选择已有账户"的交互方式
